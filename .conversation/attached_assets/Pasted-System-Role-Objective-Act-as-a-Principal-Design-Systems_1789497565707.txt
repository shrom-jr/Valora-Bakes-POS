System Role & Objective:
Act as a Principal Design Systems Architect and Senior Full-Stack Engineer with 20 years of experience building high-performance, multi-million-dollar retail applications. Your task is to construct Phase 1: Foundation, PWA Shell, and Cloud Authentication for a mission-critical, enterprise-grade Point of Sale application tailored for mobile-first bakery operations.

Do not produce an amateur template, basic tutorial layout, or generic chatbot output. The user interface, motion physics, color contrast, and code structure must reflect the quality of a premier Silicon Valley enterprise product.

---

Design System & Visual Language:
- Color Palette & Contrast Architecture:
  - Foundation: Deep Obsidian and Slate surfaces (ultra-dark backgrounds with rich depth, avoiding flat pitch-black).
  - Surfaces & Elevation: Layered card hierarchies with micro-borders (hairline borders with very subtle opacity) and soft ambient shadows to create distinct depth without harsh lines.
  - Typography & Contrast: High-contrast pure white for primary labels and headers; clear, crisp off-white for secondary metadata. Strictly forbid washed-out or low-contrast gray-on-gray text.
  - Accent & Brand System: A focused, high-end warm amber/gold primary accent for retail brand authority, balanced by a sharp emerald accent for successful actions and active indicators.
- Typography:
  - Clean, modern geometric sans-serif styling with strict visual hierarchy.
  - All numeric data, timestamps, and rupee amounts must use tabular, monospaced figures to prevent layout shifting during updates.
- Micro-Interactions & Animation Physics:
  - Every interactive element (buttons, cards, inputs) must feature tactile spring-physics feedback: an immediate, subtle scale-down on active press, followed by an elastic release.
  - Transitions between screens must feel seamless with fluid opacity shifts and subtle vertical hardware-accelerated translations.
  - Loading states must use shimmering skeleton pulses matching exact component footprints instead of crude spinner wheels.

---

PWA & Mobile-First Device Optimization:
- Native App Shell Experience:
  - Configure the application as a standalone Progressive Web App (PWA) with full-screen capability, hiding the browser navigation bar, URL bar, and footer controls entirely when launched from a mobile home screen.
  - Set touch action rules to prevent double-tap zoom delays and unwanted pull-to-refresh rubber-banding on mobile screens.
  - Implement an edge-to-edge layout utilizing safe-area insets for modern mobile display notches and bottom home indicators.
- Adaptive Responsive Canvas:
  - Mobile Default: Optimized entirely for single-thumb handheld navigation.
  - Desktop / Laptop Breakpoint: Gracefully expands into a balanced wide-screen counter workspace that adapts fluidly without breaking spacing or requiring separate mobile/desktop layouts.

---

Functional Architecture & Screen Flows:
1. Branded Splash & Bootstrapping Flow:
  - Display an instant, branded preloading splash state while the cloud connection verifies the active session.
  - Zero layout shift or flashing of unauthenticated screens during page reload.
2. Enterprise Authentication Portal:
  - A centered, glass-morphic authentication card with a subtle glowing edge border.
  - Clean input fields for Email Address and Password with floating or high-visibility labels, active focus rings, clear input error states, and a functional show/hide password toggle.
  - A full-width, prominent "Sign In" button with distinct active, loading, and disabled states.
  - Friendly, human-readable error messages for wrong credentials or network drops (no technical error codes exposed to the user).
3. Authenticated Application Shell (Phase 1 Baseline):
  - Once authenticated, transition smoothly to the primary application shell.
  - Top Command Bar: Displays the bakery name, a real-time cloud connection status indicator (green pulse for online), a prominent "Dashboard" navigation anchor, and a secure "Sign Out" control.
  - Main Content Viewport: A structured, empty container with high-contrast placeholder indicators ready to receive the POS register grid in Phase 2.
  - Session Persistence: Ensure user authentication state persists reliably across browser refreshes and device lockouts.

---

Technical Rules & Data Boundaries:
- Build the application using modern, standard frontend web technologies (Vite, React, Tailwind CSS, Lucide icons, and the official Firebase SDK).
- Environment & Firebase Isolation: Isolate all Firebase credentials into a dedicated environment configuration file using clear, uppercase placeholder variables (such as API Key, Auth Domain, Database URL, Project ID, Storage Bucket, Messaging Sender ID, App ID) so credentials can be inserted in one central spot without editing application logic.
- Enforce strict route guards: unauthenticated access to the main shell must be completely blocked, redirecting immediately to the authentication portal.
- Zero Mock Data: Do not generate hardcoded fake menu items, sample categories, or dummy data files. The architecture must initialize as a completely clean, dynamic slate ready for live cloud storage.
- Provide a production-ready, modular project structure with clear separation between UI components, authentication contexts, and styling tokens.
